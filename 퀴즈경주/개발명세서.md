# 모둠 퀴즈 레이스 개발명세서

작성일: 2026-10-17 · 상태: 설계 완료, 구현 및 배포 전

이 문서는 대화에서 확정한 요구와 구현을 위한 제안 기본값을 구분한다. `가정`은 사용자가 수치나 세부 동작까지 확정한 사항이 아니며 구현 시 변경할 수 있다. 기존 작업공간의 다른 프로그램과 분리해 개발한다.

## 1. 프로젝트 기본 정보

- 가칭: 모둠 퀴즈 레이스.
- 소개: 최대 6모둠이 각자 퀴즈를 풀고, 정답 수에 따라 교실 화면의 자동차가 전진하는 웹게임.
- 배경과 목적: 모둠 학습에 참여 동기를 부여하고 교사가 진행 상황을 한눈에 확인한다.
- 해결할 문제: 여러 모둠의 풀이 현황을 수동 집계하는 부담.
- 성공 기준: 교사가 엑셀 등록부터 방 생성, 6모둠 입장, 진행, 결과 확인, 데이터 삭제까지 수행한다. 모둠 기기는 경주 대신 문제 풀이에 집중한다.

## 2. 사용자 정의

| 사용자 | 목표 | 권한 |
|---|---|---|
| 교사 1명 | 문제 보관, 수업 진행, 결과 확인 | 본인 문제 관리, 본인 방 생성·시작·조기 종료·닫기, 모둠 현황 조회 |
| 모둠 최대 6개 | 문제 풀이와 재접속 | 코드로 입장, 자기 모둠 문제·제출 결과 조회, 자기 답안 제출 |
| 운영 담당자 | 초기 계정·환경 설정, 장애 복구 | 서버 관리. 서비스 화면의 별도 관리자 기능은 MVP 제외 |

학생 개인 계정·실명·학번·연락처는 수집하지 않는다. 모둠명에는 학생 이름을 쓰지 않도록 안내한다.

## 3. 사용 환경과 실행 플랫폼

인터넷 주소로 접속하는 반응형 웹앱. 교사는 컴퓨터와 교실 대형 화면, 모둠은 태블릿·노트북 등 브라우저 기기 한 대를 사용한다. 설치와 동일 와이파이는 필요 없다. 인터넷 연결은 필수이며 오프라인 답안 제출은 지원하지 않는다. 연결 중단 후 같은 브라우저에서 복구한다. 지원 목표는 Chrome·Edge·Safari의 배포 시점 최신 안정판이며 실제 학교 기기로 검증한다.

## 4. 핵심 사용자 시나리오

| 시나리오 | 시작 조건·행동 | 시스템 반응·완료 | 예외 |
|---|---|---|---|
| 문제 등록 | 로그인한 교사가 양식에 맞는 엑셀 선택 | 검증 미리보기 후 저장, 문제 목록에 표시 | 오류 행·열 안내, 전체 저장 취소 |

| 퀴즈 진행 | 교사가 시작, 모둠이 보기 선택 후 제출 | 서버 채점, 정답이면 전진, 오답이면 해설 | 통신 실패 시 확정 여부 조회 후 재시도 |

## 5. 사용자 흐름

교사: 로그인 → 문제 세트 목록 → 엑셀 검증·저장 → 세트 선택 → 방 생성 → 입장 현황 확인 → 시작 → 경주·풀이 현황 확인 → 자동 또는 조기 종료 → 결과 확인 → 결과 닫기 및 삭제.

모둠: 참여 페이지 → 코드·모둠 이름 입력 → 대기 → 문제 선택·제출 → 정답 결과 또는 오답 해설 → 다음 문제 → 전 문제 완료 대기 → 자기 최종 결과 → 삭제 후 입장 화면.

## 6. MVP 범위

필수: 교사 이메일 로그인·재설정, 엑셀 템플릿과 검증, 문제 세트 저장·이름 변경·삭제, 참여 코드, 최대 6모둠, 4지선다·OX, 순차 풀이, 서버 채점, 2D 경주, 교사 현황, 조기 종료, 재접속, 데이터 삭제.

있으면 좋은 기능: 교사 화면 전체화면. 후속 검토: 문제 편집 UI·문제별 수업 후 해설 도구. 제외: 3D 운전, AI 출제, 학생 로그인, 성적 누적·결과 다운로드, 여러 교사의 동시 운영 제품화, 채팅, 유료 결제, 오프라인 풀이, 시간제한 게임, 문제 무작위 배치.

### 엑셀 입력 계약

실제 XLSX 파일 제작은 구현 단계에 포함한다. 첫 시트 이름 `문제`, 헤더는 다음 순서로 고정한다.

| 번호 | 유형 | 문제 | 보기1 | 보기2 | 보기3 | 보기4 | 정답 | 해설 |
|---|---|---|---|---|---|---|---|---|
| 1 | 객관식 | 2 + 3은? | 3 | 4 | 5 | 6 | 3 | 2에 3을 더하면 5입니다. |
| 2 | OX | 삼각형의 변은 3개이다. | | | | | O | 삼각형은 변이 세 개인 도형입니다. |

- 유형은 `객관식` 또는 `OX`. 객관식 정답은 정답 보기의 번호 `1`~`4`, OX 정답은 영문 `O` 또는 `X`다.
- 객관식은 보기 4개 필수. OX는 보기 칸을 비워 두고 화면에 O·X를 자동 제공한다.
- 번호는 1부터 연속한 정수, 번호 오름차순으로 출제. 중복·누락을 오류로 처리한다.
- 완전히 빈 행만 무시하며 일부 값이 있는 행은 검증한다. 앞뒤 공백은 제거한다. 추가 시트는 읽지 않고 안내한다.
- 문제·해설 필수. 수식 셀, 외부 링크, 매크로 파일, 이미지 문제는 지원하지 않는다. 모든 텍스트는 HTML이 아닌 일반 문자열로 표시한다.
- 가정: 세트당 1~100문제, 파일 2MiB 이하, 문제·해설 각 1,000자, 보기 각 200자. 초과 시 정확한 행·열과 수정 방법을 표시한다.
- 가정: 교사가 미리보기를 확인하고 저장 버튼을 눌러야 저장한다. 원본 엑셀은 서버 파일 저장소에 남기지 않고 검증한 구조화 데이터만 저장한다.

### 채점·시간·레이스 규칙

- 정답 1점, 오답·미응답 0점. 부분점수·재도전 없음. 제출 전 선택 변경 가능, 제출 후 수정 불가.
- 오답은 정답·해설과 `다음 문제` 버튼을 표시. 정답은 `정답입니다`와 같은 버튼 표시(가정). 마지막 문제는 제출 확정 시 완료이며 해설 읽기 시간은 완료 시간에 더하지 않는다.
- 풀이 시간 = 서버 완료시각 − 공통 시작시각. 미완료 모둠은 종료시각 − 시작시각. 연결 중단과 문항 사이 해설 확인 시간도 포함한다.
- 순위: 정답 수 내림차순 → 풀이 시간 오름차순. 두 값이 모두 같으면 공동 순위, 다음 순위는 건너뛴다(가정: 1, 1, 3). 정렬용 모둠 ID는 공동 순위를 깨지 않는다.
- 진행 중 순위는 잠정 순위다. 미완료 모둠의 현재 경과시간으로 계산하며 최종 순위와 다를 수 있음을 표시한다.
- 자동차 위치 = 정답 수 / 전체 문제 수 × 트랙 길이. 전부 풀어도 오답이 있으면 결승선 전에 멈춘다. 전 문제 완료는 별도 깃발·완료 배지로 표현하며 선착순 우승으로 오해시키지 않는다.
- 시작 시 참여 모둠을 고정한다. 최소 1모둠으로 시작 가능(가정), 최대 6모둠. 완료한 모둠은 제출 불가·결과 대기.
- 종료 시각 이전에 서버에서 확정한 답안만 반영한다. 클라이언트 시각·점수·정답 여부는 신뢰하지 않는다.

## 9. 디자인 기준 및 DESIGN.md 반영

기존 제공 DESIGN.md 없음. 참고: https://racing.mumuworld.com/ 의 차량 선택·경주 테마. 참고 화면에서 확인한 것은 3D 차량과 코스 선택 화면이며 퀴즈 기능을 확인한 것은 아니다. 차종·로고·모델·이미지 자산은 복제하지 않고 직접 제작한 단순 자동차 도형을 사용한다.

## 10. 데이터 요구사항

| 정보 | 생성·변경 주체 | 보관·삭제 | 백업·주의 |
|---|---|---|---|
| 교사 이메일·인증정보 | 교사·인증 서비스 | 계정 삭제까지 | 암호 직접 저장 금지 |
| 문제·정답·해설 | 교사 | 교사가 삭제 또는 계정 삭제까지 | 원본 엑셀은 교사가 보관, 무료 자동 백업 보장 안 함 |
| 방·모둠명·답안·점수·시각·토큰 해시 | 서버 | 결과 확인 후 닫기 시 삭제 | 수업 데이터 백업·통계·내보내기 없음 |
| 복구 토큰 | 서버 발급, 모둠 브라우저 보관 | 방 삭제 후 접근 시 제거, 절대 만료 | 답안·해설·이름은 영구 브라우저 저장 금지 |

가정: 종료는 `결과 확인 상태`, 결과 닫기는 `수업 종료 및 삭제`로 구분한다. 종료 상태의 서버 보관은 최대 30분, 생성 후 어떤 방이든 절대 6시간 후 만료한다. 만료 즉시 API 접근 차단, 5분 주기 작업으로 삭제하며 작업 실패는 운영 오류로 표시한다. 접속이 끊긴 브라우저의 화면·토큰은 원격 즉시 삭제를 보장할 수 없으나 다음 접속·만료 확인 시 초기화하고 토큰은 서버에서 무효화한다. 수업 데이터가 들어간 제공자 백업·WAL·인프라 로그까지 즉시 물리 삭제되는지는 별도 확인 필요이며 즉시 완전 삭제로 광고하지 않는다.

## 11. 데이터 모델

PK는 UUID, 참조 FK는 필수, 시각은 서버 timestamptz, 정답 수는 비음수 정수다. 아래 `?`는 선택 필드다.

| 엔터티 | 주요 필드·제약 | 관계·삭제 |
|---|---|---|
| teacher | auth_user_id PK, 허용 교사 계정 | teacher 1:N quiz_set·room, 본인만 접근 |
| quiz_set | id PK, owner_id FK, title text, created_at | 세트 1:N question, 소유자 삭제 시 연쇄 삭제 |
| question | id PK, set_id FK, ordinal int, type enum, prompt text, options json, answer text, explanation text | unique(set_id,ordinal), 세트 삭제 시 삭제 |
| room | id PK, owner_id FK, code text unique(active), state enum, started_at?, ended_at?, expires_at, revision int | waiting→running→results→삭제, room 1:N room_question·team |
| room_question | room_id FK, ordinal, question snapshot fields | 복합 PK(room_id,ordinal), 시작 전 생성, 원본과 독립 |
| team | id PK, room_id FK, lane int 1~6, name text, token_hash text, next_ordinal int, finished_at? | unique(room_id,lane/name), room 삭제 시 삭제 |
| answer | team_id FK, room_id, ordinal, choice text, correct bool, accepted_at, request_id UUID | PK(team_id,ordinal), unique(team_id,request_id), team 삭제 시 삭제 |

모둠명은 방 안에서 앞뒤 공백 정리 후 중복 금지, 가정 2~12자. 점수는 확정 답안에서 집계하며 캐시 필드를 두면 같은 트랜잭션으로 일치시킨다. 문제 답안과 해설은 서버 전용 권한으로 둔다. 모둠 토큰은 고엔트로피 불투명 값이며 DB에는 해시만 보관한다. 예시 데이터는 `1모둠` 등 가상 이름만 사용한다.

## 12. 시스템 구성

백엔드 필요: 여러 기기의 동기화, 교사 로그인, 문제 중앙 저장, 신뢰할 수 있는 채점·시간·권한 처리가 필요하다.

구성 제안: 정적 웹 프론트엔드 → HTTPS 서버 함수 → 관계형 DB. 교사 인증은 관리형 인증, 교사 경주 현황은 권한 검사된 상태 조회를 2초 간격으로 요청하는 기본안(가정). 학생은 시작 대기 중 2초 상태 조회, 풀이 중 5초 상태 확인 및 제출 응답으로 갱신한다. 전역 실시간 공개 채널 없이 시작해 구현과 권한을 단순화한다. 모둠은 현재 문제만 받고 정답·미래 문항을 미리 받지 않는다. 원본 파일 저장소와 외부 AI는 불필요하다.

## 13. API 및 외부 서비스

| API | 호출·입력 | 응답 | 권한·예외 |
|---|---|---|---|
| 인증·재설정 | 교사 이메일·암호 또는 재설정 요청 | 세션 또는 일반화된 안내 | 관리형 인증, 로그인·발송 제한 |

## 14. 로그인과 권한

교사 한 명의 계정을 최초 운영 설정에서 생성하고 공개 회원가입은 끈다(가정). 이메일·비밀번호 로그인과 이메일 링크 재설정 제공. 계정이 없는 학생이 교사 API를 사용할 수 없도록 서버 허용 목록 및 DB 정책을 적용한다. 교사 로그아웃 시 브라우저 세션 제거. 진행 중 세션 만료 시 재로그인하여 같은 방을 복원하고 경주는 계속 진행한다. 계정 삭제는 재인증 후 본인 문제와 방을 삭제하고 인증 계정도 삭제하는 운영 절차로 제공한다. 모둠 토큰은 그 방의 자기 답안 권한만 가진다. 같은 모둠의 여러 탭이 제출해도 문항당 한 번만 확정한다.

## 16. 개인정보·보안·접근성

수집: 교사 이메일, 모둠 가명, 일시적 답안·점수·시각. 외부 전송: 호스팅·DB·인증 제공자, 교사 이메일은 인증 메일 제공자. 외부 AI 전송 없음. 저장 리전과 제공자 로그 보관은 배포 시 실제 설정 기록. 정규 성적·출결 시스템으로 사용하지 않는다.

- 개발 전: 학교의 외부 웹서비스 접속·교사 이메일 사용·데이터 국외 처리 관련 내부 정책을 담당자에게 확인. 확인 전 가상 모둠과 비개인 문제로 시험한다.
- 개발 중: DB 행 단위 접근 정책, 서버 함수 권한, 교사 허용 목록, 코드 추측·입장 요청 제한, 입력 길이·XSS 방어, 원문 로그 금지, 토큰 만료, 종료 경합 테스트를 구현한다.
- 배포 전: 브라우저 네트워크에 미래 문제 정답이 없는지, 익명 DB 조회·다른 방 접근이 차단되는지, 실제 삭제·메일 링크·리전·제공자 보관 정책을 점검한다.
- 접근성: 보기에는 의미 있는 라벨, 결과에 상태 알림, 문제 전환 시 제목 초점, 장식 자동차는 대체 텍스트 과잉 없이 이름·순위를 별도 텍스트로 제공. 동작 줄이기 설정 준수, 점멸 금지.

이 설계 검토는 학교의 공식 승인, 법률 검토, 실제 코드 보안 감사나 클라우드 설정 점검을 대체하지 않는다.

아래는 확정된 사용자 요구가 아닌 구현 제안이다. 정확한 패키지 버전은 구현 시작 때 공식 문서·보안 상태를 확인하고 잠금 파일에 고정한다.

| 프론트엔드 | TypeScript + Vite 기반 경량 웹앱 | 화면 8개와 상태 분리, 정적 배포 가능 | React는 화면 상태가 복잡해질 때 검토. 중 |

근거: [Supabase 접근 정책](https://supabase.com/docs/guides/database/postgres/row-level-security), [Cloudflare Pages 제한](https://developers.cloudflare.com/pages/platform/limits/).

## 18. 배포 및 운영

개발·가상 데이터 테스트와 운영 환경을 분리한다. 배포 자산은 정적 빌드, DB는 버전 관리된 마이그레이션과 서버 함수, 비밀값은 서버 환경변수에 둔다. 앱스토어·개인 도메인은 필수 아님. 계정 생성·외부 배포는 이 문서 작성 범위에 포함되지 않는다.

무료 우선 운영 후보는 Cloudflare Pages + Supabase Free다. 무료라는 이유로 수업 가용성이나 영구 무료를 보장하지 않는다. 공식 문서 확인일은 2026-10-17이며 배포 직전 한도 재확인이 필요하다. Supabase 무료 프로젝트는 낮은 활동 상태가 7일 지속되면 일시 중지될 수 있으므로 수업 전에 실제 API 접속과 복구 여부를 확인한다. [요금](https://supabase.com/pricing), [일시 중지 정책](https://supabase.com/docs/guides/platform/free-project-pausing).

비밀번호 재설정 메일의 기본 발송 서비스는 테스트용이며 허용 수신자·발송 제한이 있다. 운영 발송은 사용자 이메일에 실제 도달하는 SMTP 구성을 검증해야 한다. 개인 교사 계정을 허용 수신자로 시험할 수 있어도 운영 보장으로 해석하지 않는다. 별도 메일 제공자의 무료 한도·발신자 인증·도메인 필요 여부는 미확정이다. 무료로 충족하지 못하면 해당 제한을 보고하고 사용자 동의 없이 결제하거나 재설정을 빼지 않는다. [공식 SMTP 안내](https://supabase.com/docs/guides/auth/auth-smtp).

운영자 가정: 교사 또는 제작 담당자 1명. 수업 전 로그인·메일·정상 문제 세트·2대 시험 접속·삭제 스케줄러 확인. 장애 중 접속 오류 표시, 교사에게 경주 중단 또는 조기 종료 판단 제공. 서버 자체 장애에서는 점수·종료 완료를 가장하지 않는다. 무료 DB 백업을 가정하지 말고 문제 원본 엑셀을 별도로 보관한다.

## 19. 테스트 계획

- 단위: 객관식/OX 검증, 번호 오류·부분 행·수식·초과 파일, 정답·오답·미응답, 공동 순위, 경과시간, 자동차 비율.
- 서버 통합: 동일 문항 동시 제출, 종료와 제출 경합, 7개 모둠 동시 입장, 코드 충돌, 권한·토큰 위조·만료, 문제 스냅샷 불변성.
- E2E: 교사 1세션+모둠 6세션으로 전체 흐름, 일부 완료 후 조기 종료, 재접속·중복 탭·세션 만료·자동 완료.
- 개인정보: 종료 닫기와 자동 만료 후 방 종속 행·토큰 무효화, 응답·로그 정답 선노출, 캐시·브라우저 초기화, 학생 데이터 없는 예시.
- 실제 환경: 학교 컴퓨터·태블릿의 접속, 대형 화면 가독성, Wi-Fi 전환, 메일 도달, 6모둠 동시 응답 성능 측정.
- 디자인: 6레인, 학생 화면 경주 없음, 글자 확대·키보드·대비·동작 줄이기 확인.

## 22. 위험요소와 대응

무료 서버 일시 중지 → 수업 전 실제 호출 확인. 학교망 차단 → 실제 기기 사전 접속, 같은 와이파이 필요하다고 안내하지 않음. 동시 제출·종료 → 서버 트랜잭션. 정답 유출 → 서버 전용 스키마·현재 문제 API. 모둠명 실명 입력 → 가명 안내와 길이 제한. 복구 토큰 소실 → 자동 복구 한계 표시. 무료 메일 제한 → 실제 도달 확인 전 재설정 완료 주장 금지. 삭제 작업 실패 → 접근 만료 우선·재시도·운영 오류. 원본 문제 저작권 → 교사가 사용할 수 있는 문제만 업로드. 과도한 애니메이션 → 짧은 이동·동작 줄이기.

## 23. 가정과 미결정 사항

확정: 인터넷 웹앱, 교사 1명, 6모둠, 학생 무계정, 교사 이메일 로그인, XLSX, 객관식·OX, 동일 순서·개별 속도, 오답 해설, 정답 수·시간 순위, 2D 교사 경주, 재접속, 문제 재사용, 수업 데이터 삭제, 무료 우선.

제안 가정: 프로젝트명, 교사 계정 사전 생성·공개 가입 없음, 활성 방 1개, 코드 6자리·가명 2~12자, 1~100문제·2MiB, 정답 후 수동 다음, 완전 동률 공동 순위, 결과 닫기 시 삭제·30분 결과 만료·6시간 절대 만료, 조회 주기·성능·화면 수치. 코드 생성은 암호학적 난수와 충돌 재시도, 입장 제한은 서버에서 시행한다.

배포 전 미결정: 실제 제공자 계정·리전, 메일 SMTP·무료 한도, 서비스 로그·백업 보관, 학교 정책·대상 기기, 문제 파서 안전 버전. 안전 확인 전 실제 학생 식별정보는 사용하지 않는다. 첫 버전 개발 일정은 구현자 환경 확인 후 산정하며 임의의 납기 보장은 하지 않는다.

## 24. 비개발자를 위한 쉬운 요약

선생님이 엑셀 문제를 올리고 방을 열면 6모둠이 링크로 들어와 문제를 풉니다. 맞힐 때마다 큰 화면의 자기 자동차가 앞으로 갑니다. 모두 풀거나 선생님이 끝내면 정답 수와 걸린 시간으로 순위를 정합니다. 문제는 다음 수업에 재사용하고 모둠 기록은 결과 확인 후 지웁니다. 여러 기기의 답과 시간을 맞추고 정답을 안전하게 채점하려고 인터넷 서버가 필요합니다.

## 25. 기술 선택 이유 요약

설치 없는 웹앱이 다양한 학교 기기에 적합하다. 6대 자동차는 HTML·CSS·SVG로 충분하다. 관계형 DB는 문제 세트·방·모둠·답안의 연결과 중복 방지에 적합하다. 관리형 인증·DB로 서버 관리량을 줄이고 정적 호스팅에 화면을 배포한다. 단일 컴퓨터 시제품은 더 단순하지만 인터넷 6모둠 참여와 저장·권한을 충족하지 못하므로 최종 서비스의 대안은 아니다.
