## 자동 검사

- `npm run build`: TypeScript 검사와 Vite 실행용 빌드 통과.
- `npm test`: **21개 통과, 0개 실패**. 아래 주요 범위를 포함한다.
- XLSX 양식은 Artifact Tool로 작성·렌더링 후 ExcelJS 호환을 위해 동등한 XML 네임스페이스 표기만 정규화했다. 저장 파일을 실제 앱 파서로 다시 읽어 객관식·OX·정답·해설을 확인했다.
- 수식·하이퍼링크·잘못된 형식·해제 크기 초과, 4지선다/OX·번호·누락값·길이 검증.
- 7개 동시 입장에서 6개만 성공, 동일 이름·시작 후 신규 입장 차단.
- 현재 문항 정답 은닉, 중복 제출 1회 채점, 오래된 요청 ID 재사용 거절, 지연된 이전 문항 이동이 새 해설을 건너뛰지 않음.
- 조기 종료·제출 경합, 미응답 0점, 완료/미완료 시간, 공동 순위, 접속 중단 시간 포함, 절대 만료.
- 교사·모둠 권한, 잘못된 토큰, 세트 사용 중 삭제 금지, 원본 변경과 방 스냅샷 분리.
- 방 삭제 시 모둠·답안·문제 스냅샷 삭제 및 저장 세트 보존, 토큰 무효화, 교사 삭제 연쇄 처리.
- 로컬 실제 HTTP 서버에서 6개 독립 모둠 토큰의 입장·제출·재조회·자동 종료·삭제. 최근 측정 6모둠 동시 제출 p95 **85.3ms**. 로컬 컴퓨터의 작은 표본이며 인터넷·학교망 성능을 의미하지 않는다.
- 내부 SMTP 시험 서버에서 재설정 메일 생성·발송, 일회용 링크·비밀번호 변경·기존 세션 무효화.
- Supabase 로그인·getUser 검증·재설정 어댑터는 **모의 응답 계약 검사**. 실제 Supabase 연결 시험은 아님.
- 의존성 조정 후 `npm audit`: 알려진 취약점 **0건**. 이 결과가 전체 소스 보안 감사나 향후 안전을 보장하지는 않는다.

## 브라우저 직접 확인

로컬 Chromium 계열 브라우저에서 가상의 교사·모둠으로 다음을 수행했다.

1. 첫 화면 → 초기 교사 계정 생성 → 실제 XLSX 파일 선택 → 미리보기 → 세트 저장 → 방 생성.
2. 모둠 하나는 브라우저로, 나머지 5모둠은 실제 API 참가자로 입장. 교사 화면에서 6개 레인·정원·현황 확인.
3. 교사 시작 → 모둠 새로고침 후 현재 문제 복원 → 객관식 오답 제출 → 정답·해설 → 다음 OX 정답 제출 → 결과 확인.
4. 서로 다른 서버 점수로 자동차 위치가 0%, 50%, 100%에 표시됨을 확인. 화면을 다시 만들지 않고 갱신하도록 조정.
5. 교사 조기 종료 → 최종 순위·풀이 시간·미완료 상태 → 결과 닫기 및 삭제 → 교사 세트 보존, 모둠 새로고침 시 새 입장 화면과 토큰 초기화 확인.
6. **360×800** 모둠 화면: 문서 폭 360px, 가로 넘침 없음, OX 선택지 2개, 경주 요소 없음.
7. **1280×720** 교사 화면: 자동차 6개·레인 6개, 마지막 레인 하단 약 647px로 한 화면 안에 표시. 아래 상세 표는 스크롤 조회.
