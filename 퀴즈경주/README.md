# 모둠 퀴즈 레이스

최대 6모둠이 같은 문제를 각자 속도로 풀고, 교실 화면의 자동차가 정답 수에 따라 전진하는 웹앱입니다. 학생은 설치·가입 없이 참여 코드와 모둠 별명으로 입장합니다.

## 바로 실행하기

1. **Node.js 24 이상**이 설치된 컴퓨터에서 이 폴더의 **실행.bat**를 실행합니다.
2. 브라우저에서 **http://localhost:4317** 을 엽니다.
3. **교사로 시작하기**에서 처음 한 번 이메일과 비밀번호(12자 이상)를 등록합니다.
4. 엑셀 문제를 올리거나 **예시 6문제 등록**을 눌러 수업 흐름을 확인합니다.

서버를 종료하려면 실행 창에서 Ctrl+C를 누릅니다. 기본 실행은 교사 컴퓨터의 로컬 시험용입니다. `localhost` 주소는 학생의 다른 기기에서 사용할 인터넷 주소가 아닙니다. 인터넷 수업에는 아래 운영 설정과 배포가 필요합니다.

직접 명령으로 실행할 수도 있습니다.

```powershell
npm ci
npm run build
npm start
```

포트를 바꾸려면 `.env.example`을 `.env`로 복사하고 PORT와 APP_ORIGIN을 함께 바꿉니다. `.env`와 `data/`는 소스 저장소에 올리지 않습니다.

## 수업 진행

- 교사 화면: `/teacher`, 모둠 화면: `/join`.
- 문제 보관함에서 **이 문제로 수업 열기** → 참여 코드·링크 공유 → 최대 6모둠 입장 → **경주 시작**.
- 학생은 문제를 선택하고 제출합니다. 정답·오답을 확인한 다음 **다음 문제**를 누릅니다. 오답에는 정답과 해설이 나옵니다.
- 정답 1개당 자동차가 전체 트랙의 `1 / 문제 수`만큼 전진합니다. 모든 문제를 풀었다고 자동차를 결승선까지 이동시키지 않습니다.
- 전 모둠이 완료하면 자동 종료합니다. 교사는 **조기 종료**할 수도 있습니다. 미응답은 0점입니다.
- 정답 수 내림차순, 동점이면 서버 풀이 시간 오름차순입니다. 완전히 같으면 공동 순위입니다. 시간은 밀리초까지 표시합니다.
- **결과 닫기 및 삭제**는 모둠 이름·답안·점수·방의 문제 복사본을 삭제합니다. 교사의 저장 문제는 남습니다.
- 같은 브라우저의 새로고침·재접속은 토큰으로 복구합니다. 저장소 삭제·시크릿 창·다른 기기에서는 자동 복구할 수 없습니다. 연결 중단 동안에도 시간은 계속 흐릅니다.
- 학생 이름 대신 가상의 모둠 별명을 사용하세요.

## 엑셀 문제 양식

앱의 **엑셀 양식** 버튼 또는 `public/문제양식.xlsx`를 사용합니다. 첫 시트 이름은 `문제`, 열 순서는 아래와 같습니다.

```text
번호 | 유형 | 문제 | 보기1 | 보기2 | 보기3 | 보기4 | 정답 | 해설
```

객관식은 보기 4개와 정답 보기 번호 1~4, OX는 빈 보기 칸과 영문 O/X 정답을 입력합니다. 문제와 해설은 필수입니다. 번호는 1부터 연속해야 합니다. 완전히 빈 행은 무시합니다. 세트당 1~100문제, 파일 2MiB 이하, 문제·해설 각 1,000자, 보기 각 200자입니다.

수식·하이퍼링크 개체·매크로·삽입 개체·이미지 문제·외부 통합문서 링크는 지원하지 않습니다. 다른 시트는 읽지 않습니다. 파일 내부 압축 해제 크기는 20MiB로 제한합니다. 검증 오류가 있으면 아무 문제도 저장하지 않습니다. 원본 XLSX는 서버에 보관하지 않습니다.

## 구현 구조와 명세 대비 조정

화면은 TypeScript + Vite + HTML/CSS/SVG입니다. 게임은 실제 Node HTTP 서버에서 처리하며 localStorage로 여러 모둠을 흉내 내는 구조가 아닙니다.

명세의 기술 스택은 제안 사항이었으며, 외부 계정 없이 검증할 수 있도록 **로컬 SQLite + 운영 PostgreSQL** 어댑터를 작성했습니다. 같은 게임 로직을 두 DB에서 사용합니다. 인터넷 운영 인증은 **Supabase Auth**, 데이터는 **Supabase PostgreSQL**을 사용하도록 연결 코드를 제공합니다.

제안했던 Edge Functions·정적 Pages 분리 대신 **Node 서버가 화면과 API를 같은 주소로 제공**합니다. 서버 자체가 필요하므로 `dist/`만 Cloudflare Pages에 올리면 온라인 게임이 동작하지 않습니다. Node/Docker를 지원하는 호스트에 앱을 배포해야 합니다. 운영용 Dockerfile을 포함했습니다. 실제 외부 배포·계정 생성·결제는 수행하지 않았습니다.

```text
src/                 화면, 스타일, 엑셀 파서
shared/              문항 검증, 순위·시간·위치 규칙, XLSX 안전 검사
server/index.ts      HTTP API, 쿠키, 출처 검사, 정리 스케줄러
server/game.ts       서버 채점·수업 상태·재접속·종료
server/auth.ts       로컬 인증/SMTP와 Supabase 인증 어댑터
server/db.ts         SQLite/PostgreSQL 트랜잭션 어댑터
server/schema.sql    초기 DB 마이그레이션 (재실행 가능)
server/*postgres.sql 운영 권한 강화·독립 만료 정리 작업
tests/               규칙·인증·엑셀·HTTP 통합 테스트
public/              내려받는 실제 XLSX 양식
dist/                실행용 화면 빌드
```

## 인터넷 운영 설정

현재 외부 프로젝트·메일 제공자 정보가 없어서 실제 인터넷 연결과 메일 수신은 검증하지 않았습니다. 아래 설정을 완료한 뒤 가상 모둠으로 인수검사하세요.

1. **Supabase 준비**: 프로젝트 생성, 교사 이메일 계정 등록, 공개 가입 비활성화. 사용할 리전·기관 정책을 확인합니다.
2. **DB 연결**: 서버 전용 DATABASE_URL에 프로젝트 Connect 화면의 PostgreSQL 접속 문자열을 설정합니다. 상시 Node 서버에는 Direct 또는 Session pooler를 우선 검토하고 실제 네트워크의 IPv4/IPv6 지원을 확인합니다. 이 앱의 연결에서는 인증서를 검증합니다. 인증서 오류가 나면 제공자 인증서를 올바르게 신뢰하도록 설정하고 검증을 끄지 마세요.
3. **호스트 설정**: Node 24 이상, 설치 `npm ci`, 빌드 `npm run build`, 시작 `npm start`. 또는 Dockerfile 사용. HTTPS 접속 주소를 확보합니다.
4. **환경변수**: `NODE_ENV=production`, `HOST=0.0.0.0`, `PORT`(호스트 할당값), `APP_ORIGIN=https://실제주소`(끝 슬래시 없음), `DATABASE_URL`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `TEACHER_EMAIL`을 설정합니다. 민감한 접속 문자열은 호스트의 Secret 설정에만 넣습니다. 운영 변수 누락 시 서버가 실행을 거절합니다.
5. **DB 권한**: 첫 서버 시작 시 `quiz_private` 스키마와 표가 생성되고 공개 권한 회수·RLS가 적용됩니다. Supabase SQL Editor에서 `server/privacy-postgres.sql`을 추가 적용합니다. `quiz_private`를 API exposed schemas에 추가하지 마세요. 서버는 해당 스키마를 소유한 DB 역할로 접속합니다. 브라우저는 DB에 직접 접근하지 않습니다.
6. **독립 정리**: 스키마 생성 후 `server/cleanup-postgres.sql`을 적용합니다. 앱 호스트가 휴면이어도 DB가 실행 중이면 5분마다 방과 만료 토큰을 정리합니다. cron 실행 이력과 실패 여부를 확인합니다.
7. **메일**: Supabase Auth의 Site URL과 허용 Redirect URL에 실제 주소 및 `/teacher?recovery=1`을 설정하고 Implicit flow의 기본 복구 메일 링크를 사용합니다. 앱이 fragment의 recovery access_token을 받아 서버에서 검증하고 비밀번호를 바꿉니다. PKCE code 전용 메일 템플릿으로 임의 변경하지 마세요. 일반 수신자 발송에는 운영 SMTP 설정과 실제 수신 시험이 필요합니다.
8. **시험**: 교사 로그인·재설정 링크 수신·새 비밀번호 로그인, 모둠 6기기, 7번째 입장 차단, 조기 종료, 새로고침, 삭제, 만료, 익명 DB 접근 거절을 확인합니다. 학교 기기로 서버를 열 수 있는지도 확인합니다.

Supabase 인증용 공개 키는 브라우저 번들에 넣지 않아도 이 서버가 사용합니다. 서비스 역할 키는 앱 실행에 필요하지 않습니다. PostgreSQL URL·SMTP 비밀번호·교사 비밀번호를 소스나 로그에 쓰지 않습니다.

## 무료 운영의 실제 제한

2026-10-17 확인 기준이며 배포 직전 다시 확인해야 합니다. 계정별 자격·한도와 제공자 정책은 달라질 수 있습니다. 현재 앱은 유료 결제·계정 생성·외부 업로드를 실행하지 않습니다.

- [Supabase Free](https://supabase.com/pricing)는 사용량 제한과 [저활동 프로젝트 일시 중지](https://supabase.com/docs/guides/platform/free-project-pausing)가 있습니다. 수업 전에 실제 API를 열어 확인하세요.
- [Supabase 기본 메일 발송](https://supabase.com/docs/guides/auth/auth-smtp)은 테스트용입니다. SMTP 미설정 상태에서 일반 이메일의 재설정 발송을 보장하지 않습니다.
- Node 호스트 예시인 [Render Free](https://render.com/docs/free)는 15분 유휴 시 중지되고 재기동에 시간이 필요합니다. 파일이 휘발성이므로 **운영 SQLite를 사용하면 안 됩니다**. 외부 PostgreSQL이 필요하며 무료 이용에는 가용성·사용량·발송 포트 등 제한이 있습니다. 수업용 안정성을 보장하지 않습니다.
- 무료 서버/DB의 중지·장애 중에는 물리 정리 작업을 정시에 수행할 수 없습니다. 앱 API는 만료 시각이 지난 데이터에 즉시 접근을 거절합니다. DB가 다시 실행되면 정리 작업을 확인하세요.

무료 범위로 실제 요구를 충족하지 못하면 제한을 먼저 확인하고, 자동 결제 또는 기능 축소 없이 운영 방식을 결정해야 합니다.

## 로컬 메일과 계정 관리

로컬 계정에서 메일을 시험하려면 `.env`의 SMTP_URL과 MAIL_FROM을 설정합니다. 서버는 30분짜리 일회용 복구 링크를 보냅니다. SMTP 미설정이면 화면에 명확한 오류를 표시합니다. 테스트에서는 내부 SMTP 시험 서버로 발송·재설정·세션 무효화를 검증했지만 외부 받은편지함 수신은 확인하지 않았습니다.

교사 로그아웃 시 해당 세션은 삭제됩니다. 세션은 최대 12시간입니다. 앱을 통한 비밀번호 재설정은 기존 세션을 무효화합니다. 운영 계정 비활성화 시에는 Supabase Auth 계정 처리와 함께 앱 DB의 해당 `teacher_session`도 삭제해야 합니다.

계정 전체 삭제는 신뢰할 수 있는 운영자가 서버에 인증하여 `npm run account:delete`를 실행하는 관리 절차로 제공합니다. 이메일·삭제 문구·현재 교사 비밀번호를 확인하며 문제와 수업도 함께 삭제합니다. 비밀번호는 화면에 표시되지 않으며 비대화형 실행은 거절합니다. Supabase 모드는 재인증 후 운영자가 Auth에서 계정을 삭제하고 앱 DB 자료 삭제를 진행해야 합니다. 일반 교사 화면에는 계정 삭제 버튼이 없습니다. 운영자 서버 접근 권한을 학생에게 주지 마세요.

## 보관과 삭제

문제는 교사가 삭제할 때까지 보관합니다. 로컬 SQLite는 `data/quiz.sqlite`에 저장되며 파일을 잃으면 문제도 사라집니다. 원본 엑셀을 별도 보관하세요. 수업 중인 DB를 무작정 복사하여 백업하지 마세요.

모둠 데이터는 결과 닫기 시 연쇄 삭제, 결과 상태 최대 30분·방 생성 후 최대 6시간에 만료합니다. 실행 중인 앱은 5분마다 정리합니다. 운영 DB에는 독립 cron을 설정하세요. 브라우저에는 복구 토큰만 저장하고 답안·정답을 영구 저장하지 않습니다. 오프라인 브라우저의 화면·제공자 백업·로그·WAL까지 즉시 물리 삭제되는 것은 보장할 수 없습니다. 제공자 보관 정책을 확인해야 합니다.

## 검사와 운영

```powershell
npm run check
npm audit
```

`검증결과.md`에 실제 검사 범위와 외부 연결 미검증을 기록했습니다. 엑셀 파서는 교사 등록 때만 지연 로딩되어 큰 청크 경고가 있지만 모둠의 기본 화면에는 최초 로딩되지 않습니다. 자동 테스트는 학교 실제 기기·네트워크 시험을 대신하지 않습니다.

`/api/health`의 200 응답은 서버·직전 정리 상태 점검입니다. 메일 수신이나 모든 화면의 정상 동작을 보장하는 신호가 아닙니다. 수업 전 2기기로 간단히 시작·답안·결과·삭제를 확인하세요.

업데이트 시 `npm ci` → `npm run check` → 서버 재시작을 수행합니다. DB 최초 스키마는 재실행할 수 있지만 향후 열 변경은 별도 마이그레이션으로 관리해야 합니다. 롤백은 이전 코드와 잠금 파일로 빌드한 후 DB 스키마 호환성을 확인하고 적용합니다. 수업 진행 중 업데이트하지 않습니다.
